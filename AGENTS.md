# Agent instructions

## Dependencies

When selecting, adding, upgrading or reviewing dependencies, check live authoritative
registries and upstream guidance for the latest listed stable compatible versions,
deprecations/replacements, vulnerabilities and license/redistribution terms,
including transitive dependencies. Prefer a coherent stable set. Explain exceptions
and validate with relevant builds/tests. Never silently retain deprecated,
vulnerable or prerelease packages, or claim complete security from an advisory scan.

## Release notes

Keep each changelog/release-note entry compact: one short sentence describing the
user-visible change. Combine closely related changes and avoid implementation
narratives, command examples, repetition and long caveats. Put technical details,
integration instructions and validation evidence in the relevant documentation.
Keep material limitations brief and explicit. Do not rewrite older release entries
unless requested.
